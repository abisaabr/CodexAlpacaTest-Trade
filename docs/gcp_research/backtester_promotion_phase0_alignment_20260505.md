# Backtester And Promotion Phase 0 Alignment

Generated: 2026-05-05

## Scope

This is a safe control-plane/code alignment pass for the research backtester and promotion-review chain. It does not start trading, does not start or restart a broker-facing paper session, does not modify live manifests, and does not change the `fill_coverage >= 0.90` promotion gate.

## Changes

- `scripts/run_option_aware_research_backtest.py` now reports the run-level `fill_coverage_unit` as `filled_option_structures_per_source_stock_trade`, matching the actual promotion semantics for option structures.
- `scripts/build_research_promotion_review_packet.py` now preserves source portfolio-report `blocker_counts` when available, records the blocker-count scope, and also emits `top_candidate_blocker_counts` separately.
- `scripts/analyze_option_fill_failures.py` now labels output as diagnostic-only, carries candidate identity context, and records basic promotion-gate context without pretending to be a promotion packet.
- `tests/test_analyze_option_fill_failures.py` adds coverage for diagnostic scope, identity context, and gate-context preservation.
- `tests/test_build_research_promotion_review_packet.py` now verifies full-population blocker counts are not collapsed into top-candidate-only blocker counts.

## Why This Matters

The research system must keep three concepts separate:

- Raw data foundation coverage: whether selected contract-days have market data.
- Strategy fill coverage: whether a candidate's intended option structures can be priced for source stock trades.
- Promotion-review eligibility: whether the candidate clears fill, trade count, PnL, drawdown, loser-cluster, and portfolio-context gates.

The previous packet shape could understate blockers when only top candidates were inspected. The updated packet preserves full-population blocker counts when generated by the portfolio report, while still exposing top-candidate blockers for triage.
